# 02 — 求解器

本專案唯一的 ground truth 來源。實作在 [`thermoforge/solver.py`](../thermoforge/solver.py)。

## 解的方程

板級熱傳導的薄板（fin）近似——板面內傳導，上下表面對流散熱到環境：

```
∇·(kt ∇θ) − h·θ + p(x, y) = 0
```

| 符號 | 意義 | 單位 |
|---|---|---|
| θ = T − T_amb | 溫升 | K |
| kt | 片導熱（導熱係數 × 板厚） | W/K |
| h | 上下表面對流係數**總和** | W/m²K |
| p | 面功率密度 | W/m² |

除以 kt 得到**螢幕化 Poisson 方程**（modified Helmholtz）：

```
∇²θ − m²θ = −f,    m² = h/kt,    f = p/kt
```

`1/m = √(kt/h)` 是**熱擴散長度**：一個點熱源的影響大約在這個尺度之外衰減掉。
它決定了整個問題的空間尺度，也是代理模型最需要看懂的那個量。

邊界條件四邊絕熱（∂θ/∂n = 0）——板緣的傳導散熱相對於整面對流可忽略。

## 為什麼挑這個方程

不是因為它簡單，是因為它同時給了**三種互相獨立的正確性檢查**。這在
「資料是自己生成的」這種專案裡特別重要：沒有外部真值可以對，就必須靠內部一致性。

| 性質 | 換到什麼 |
|---|---|
| **線性** | 沒有迭代收斂的模糊地帶；同一輸入永遠同一輸出【已確認：`test_solver_is_deterministic`】 |
| **有解析 Green's function** G(r) = K₀(m·r)/(2π) | 物理基準不是玩具，遠離邊界處誤差 < 5%【已確認：`test_free_space_greens_matches_solver_far_from_boundaries`】 |
| **有精確守恆律** h·∫θ dA ≡ P_total | 抓得到「求解器自己壞了」【已確認：4400 列的最大殘差 5.2e-15，見 v1.manifest.json】 |

守恆律是恆等式而不是精度指標。它一旦不成立，壞掉的是求解器、離散化或功率圖，
不是「這批資料比較難」——所以 `data/generate.py` 在生成迴圈裡逐樣本檢查，
超過 1e-9 直接中止而不是把資料寫出去。

## 離散化

Cell-centered 有限體積，均勻網格，5 點 Laplacian。絕熱邊界以「略去該面」實作，
於是通量在內部逐面抵銷，守恆律在**離散層級**就精確成立（不是收斂到）。

功率圖用面積加權離散化，而不是「元件中心落在哪一格就全給哪一格」。
理由是守恆檢查的前提：離散化若偷改了總功率，那個檢查就失去鑑別力。
元件小於一格時，最近鄰指派的總功率誤差可以到數十 %【已確認：`test_rasterize_subcell_component_conserves_power`】。

## 兩份實作，互為對照

| 實作 | 方法 | 64×64 一筆 |
|---|---|---|
| `solve_theta_dct`（預設） | DCT-II 對角化，逐模態除法 | **0.263 ms** |
| `solve_theta_sparse`（參考） | 組稀疏矩陣直接解 | 9.99 ms |

【已確認：2026-09-07 本機實測，200 筆平均】

留兩份不是重複。DCT 版依賴一個容易寫錯而且**不會報錯**的東西——餘弦基底下
Neumann 二階差分算子的特徵值公式。寫錯了它不會丟例外，只會安靜地給出錯的溫度場，
而錯的場長得跟對的場一樣合理。稀疏版不共用那個假設，所以
`test_dct_matches_sparse` 是這個檔案裡唯一能抓到那類錯誤的東西。

（這是繼承自 `.claude/` 的 L0005「系統說壞了的時候，第一個嫌疑犯是你的判定條件」的
另一面：判定條件正確的時候，第一個嫌疑犯是**只有一份實作的那個計算**。）

## 這個求解器有多快 —— 以及它對本專案結論的影響

**0.263 ms/筆。代理模型是 0.32 ms/筆。所以在本 repo 內，代理模型沒有速度優勢。**

這件事必須寫在這裡，因為 `docs/01-problem-statement.md` 第 1 題的動機是
「數值求解太慢，所以一輪只試得起個位數方案」。那個前提**對真實 CFD 成立，對這個求解器不成立**。

原因是結構性的：這個求解器快，是因為問題線性、網格均勻、二維——
而那正是真實 CFD 沒有的三個性質（流場非線性、非結構化網格、三維）。
DCT 對角化在那裡完全不適用。

所以誠實的宣稱只有這幾條：

| 宣稱 | 等級 |
|---|---|
| 代理模型在本求解器定義的問題上，比工程師手算的解析近似準一個數量級 | 已確認（見 `docs/05-results.md`） |
| 本專案的切分設計、OOD 探針與守恆檢查，換到昂貴的求解器仍然成立 | 推論：這些機制不依賴求解器的實作，只依賴「有 ground truth 可生成」 |
| 代理模型換到真實 CFD 上會有數量級的加速 | **未驗證**——本 repo 沒有 CFD，這條不能當結論用 |

把便宜的求解器當缺點是誤讀。它是**刻意的方法學選擇**：ground truth 便宜到可以
無限生成，才量得出精確的 OOD 誤差與精確的守恆殘差——那些量在 ground truth
一筆要跑四個 CPU 小時的時候，根本量不出來。
