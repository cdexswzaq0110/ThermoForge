# 07 — Model Card

> 數字區塊在 [05-results.md](05-results.md)，本檔不重複。這裡管的是
> **這個模型可以拿來做什麼、不可以拿來做什麼、在哪會錯。**

## 這是什麼

一個把「板級功率佈局」映射到「穩態溫度場」的神經代理模型。
輸入是 64×64 的無因次功率圖與兩個無因次數 (m·Lx, m·Ly)，輸出是無因次溫升場，
再乘回該樣本的溫度尺度得到 °C。

| 項目 | 值 |
|---|---|
| 版本 | v0.1 |
| 架構 | FiLM 條件化 U-Net，0.91 M 參數 |
| 訓練資料 | `data/processed/v1.npz` 的 id 子集，3600 列 / 900 個 base layout |
| Ground truth | 本 repo 內建的二維穩態熱傳導有限差分求解器 |
| 訓練環境 | Python 3.11.15 / torch 2.5.1+cu121 / RTX 3060 |

## 預期用途

**在早期佈局階段，對候選佈局做熱點溫度的排序，篩出值得送求解器／CFD 確認的少數幾個。**

使用者是熱設計工程師。決策是「這個佈局要不要送下一關」，不是「這個佈局合不合格」。

## 明確**不**適用

| 不做 | 為什麼 |
|---|---|
| **取代 CFD** | 本 repo 內沒有 CFD 參考解，這個比較在這裡算不出來。上限宣稱只到「在本求解器定義的問題上」 |
| **暫態、流場、輻射、三維堆疊** | 求解器不解，模型學不到 |
| **合格判定** | 篩選工具的錯誤成本模型是「漏掉好方案」，不是「放過壞方案」。判定要由數值方法做 |
| **真實 PCB 的溫度預測** | 訓練資料是模擬的，沒有量測雜訊、沒有材料不均、沒有散熱片。這條差距沒有被量化過 |
| **散熱片、熱管、局部強制對流** | 物理模型只有單一均勻的 h 與 kt，表達不了局部散熱結構 |
| **推出訓練分佈的任何查詢** | 見下方「什麼時候不要相信它」 |

## 什麼時候不要相信它

設計副駕用 `check_in_distribution` 做機械化守門。以下任一軸落在區間外，
輸出一律標**未驗證**，不給區間，並要求送求解器：

| 軸 | 訓練分佈 |
|---|---|
| 板長 Lx | 0.12 – 0.25 m |
| 長寬比 Lx/Ly | 0.80 – 1.25 |
| 片導熱 kt | 0.08 – 0.30 W/K |
| 對流係數 h | 15 – 80 W/m²K |
| 環境溫度 | 20 – 45 °C |
| 熱點溫升（解析估計） | 15 – 90 K |
| 元件數 | 3 – 7 |

**分佈外的數字不是「比較不準」，是沒有證據支持。** 這是
`.claude/rules/evidence-grades.md` 的直接後果，也是本專案把它做成程式碼的地方。

除了分佈檢查，還有兩個**不需要真值**的信號可以在推論時算：

- **能量守恆誤差**：|h·∫θ̂ dA − P| / P。模型沒有被要求滿足這條，所以它偏離得越多，
  這一筆越可疑。
- **PDE 殘差**：把預測代回方程，看它違反多少。解析下限是 1e-7（資料存 float32）。

兩者都在 `thermoforge/diagnostics.py`，且對真實部署最有價值——**上線之後沒有真值，
但這兩個量算得出來**。

## 風險與誤用

| 風險 | 緩解 |
|---|---|
| 有人把「代理模型說 78 °C」當成合格證明 | 副駕的輸出一律帶證據等級；`optimize` 路徑回報的是**求解器確認過**的數字 |
| 有人把本專案的分數外推到真實 CFD | `CLAUDE.md` 與 `docs/02-solver.md` 的證據邊界段落；review 時視為缺陷 |
| 餘裕很小的時候被當成安全 | 餘裕小於模型低估 p95 時，副駕明說「這個結論不夠穩」 |
| frozen holdout 被反覆偷看 | `thermoforge.frozen` 需要 `--confirm` 並寫解凍帳本 |

## 監控（若要上線）

**本專案沒有上線，所以以下是設計而非實測**【未驗證】。

| 類別 | 監控什麼 | 觸發 |
|---|---|---|
| Schema | 輸入的七個軸是否在訓練分佈內 | 分佈外比例上升 → 重新取樣訓練資料 |
| 物理一致性 | 能量守恆誤差、PDE 殘差的分佈 | 中位數漂移 → 模型或輸入管線有問題 |
| 決策品質 | 送求解器確認的候選裡，代理模型排第幾 | 排序退化 → retrain |
| 成本 | 每個佈局的推論時間 | 超過 50 ms 預算 |

沒有監控的模型不算 production-ready。本專案的狀態是**原型**。
