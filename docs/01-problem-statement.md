# 01 — Problem Statement（Gate 0）

> `se-ml-lifecycle` Stage 1 的七問。**第 1 題答不出來就不要建模。**
> 本檔是後面所有 metric 與 split 決策的上游；改這裡就要回頭改下游。

## 1. 決策：誰、在什麼時間、根據預測做什麼

**熱設計工程師，在佈局定案前的早期階段，決定「這個元件擺放方案要不要送 CFD 驗證」。**

現況的瓶頸不是精度，是**吞吐量**：一次完整數值求解要數十分鐘到數小時，所以一輪設計
迭代只試得起個位數方案。真正的設計空間（7 個元件在板上的擺放）大到 10⁶ 以上，
工程師實際只探索了其中萬分之一。

代理模型要接手的是**篩選**，不是**判定**：

```
1000 個候選佈局
   → 代理模型秒級掃過，排出熱點溫度       ← 本專案負責這一段
   → 取前 20 個送求解器 / CFD 確認         ← 仍然由數值方法判定
   → 工程師從確認過的結果裡挑
```

**因此「篩選階段沒把真正的好方案漏掉」比「溫度預測絕對準」更重要。**
這一句決定了下面第 5 題與主要 metric。

## 2. 預測單位

一列 ＝ **一個佈局**（board geometry ＋ 元件位置／尺寸／功耗 ＋ 材料 ＋ 對流條件 ＋ 環境溫度）。

輸出**不是純量**，是 64×64 的溫度場。決策真正取用的是場上的最大值（熱點溫度），
但整場要一起評——只看熱點會養出一個「猜最大值」而不理解熱擴散的模型。

## 3. Target 怎麼產生、何時知道、可不可靠

由本 repo 內建的**二維穩態熱傳導有限差分求解器**求解得到（見 [02-solver.md](02-solver.md)）。

| 性質 | 狀態 |
|---|---|
| 何時知道 | 生成資料時立刻知道；沒有標籤延遲 |
| 可靠度 | 線性方程的稀疏直接解，**不是迭代近似**；同一輸入永遠同一輸出【已確認：見 `tests/test_solver.py::test_determinism`】 |
| 可回填 | 是——任何舊佈局都能重算 |
| 偏誤來源 | **求解器本身的物理簡化**，不是量測雜訊。這是本專案最大的效度限制，見下方「不做範圍」 |

**沒有 label noise 是這個 target 的特徵，不是優點。** 它代表本專案量到的泛化誤差
純粹來自模型與切分，不會被雜訊掩蓋——這讓 OOD 實驗的訊號很乾淨，
但也代表本專案的分數**不能外推**到帶量測誤差的真實熱電偶資料。

## 4. 推論當下真正取得的欄位

| 可用 | 不可用 |
|---|---|
| 板子長寬、網格解析度 | 求解器的中間迭代狀態 |
| 每個元件的位置、尺寸、功耗 | 真實量測溫度 |
| 片導熱 kt、對流係數 h、環境溫度 | 同一佈局的其他 h 條件下的解（那是兄弟樣本，見第 4 條節奏） |

全部在佈局階段就已決定，**沒有時間方向的洩漏風險**。本專案的 leakage 風險不在欄位，
在**切分**：同一 base layout 衍生的兄弟樣本若被拆到訓練與驗證兩邊，模型等於看過答案。

## 5. 錯誤成本：**不對稱**

| 錯誤 | 後果 | 代價 |
|---|---|---|
| **低估熱點**（predict < truth） | 過熱的板子通過篩選 → 一路到量產才發現 → 改版、召回 | **極高** |
| 高估熱點 | 好方案被誤篩掉 → 過度設計散熱 → BOM 成本上升 | 中 |
| 整場誤差但熱點對 | 診斷圖不可信，但決策不受影響 | 低 |

因此：

- **主要 metric**：`top-K screening recall` ——用預測熱點溫度排序後取前 K 名，
  真實最優 K 名有多少被留住。這直接量的是第 1 題的那個決策。
- **必報的守門 metric**：`under-prediction rate` ——低估超過容忍值的樣本比例。
  任何只報 MAE／RMSE 的結論視為不完整（`CONTEXT.md` 的 flagged ambiguity 第 2 條）。
- **輔助 metric**：field MAE、T_max signed error、field max abs error、推論延遲。

## 6. 基準

| 基準 | 是什麼 | 為什麼要它 |
|---|---|---|
| **A — mean field** | 預測訓練集平均溫度場 | 下限。贏不過它代表模型什麼都沒學到 |
| **B — 物理基準** | Green's function 疊加：`θ = Σ Pᵢ/(2π·kt)·K₀(m·rᵢ)` | **真正的品質底線。** 這題有解析近似解，不用它當基準等於自欺 |
| **B+ — 加鏡像源** | B ＋ 四面絕熱壁的一階鏡像源 | 把 B 的已知弱點（邊界）補掉，讓神經網路要贏的對手是誠實的 |

**神經網路要證明的不是「比平均值好」，是「比一個懂物理的人手算的近似解好」。**
如果贏不過 B+，正確結論是這個問題不需要神經網路——那也是一個結果，不是失敗。

## 7. 限制

| 限制 | 數字 |
|---|---|
| 延遲 | 單次推論 < 50 ms（要撐得住互動式設計迴圈掃 1000 個佈局） |
| 訓練資源 | 單張 RTX 3060 12GB【已確認：`nvidia-smi`】 |
| 可解釋性 | 必須能指出模型在哪一類佈局會錯，以及違反物理的位置（見 Stage 6） |
| 部署 | 純本機，無付費 API 依賴；LLM 層在沒有 key 時必須仍然可用 |

## 不做範圍（Out of scope）

**這一節與「做什麼」同等重要，寫進 Gate 0 就是為了它。**

- **不做暫態、不做流場、不做輻射、不做三維堆疊。** 求解器不解，模型也就學不到。
- **不宣稱可取代 CFD。** 本 repo 內沒有 CFD 參考解，這個比較在這裡無法計算。
  能宣稱的上限是「在本求解器定義的問題上，代理模型 vs 物理基準 vs 求解器」。
- **不做真實 PCB 資料驗證。** 沒有這種資料，也不打算假造一份來充場面。
- **不做元件佈局的自動最佳化收斂保證。** LLM 層會做隨機搜尋 ＋ 代理模型評估，
  那是**建議**，不是最佳解證明。
