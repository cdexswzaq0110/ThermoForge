# 證據等級（Evidence Grades）

**每個會被別人拿去做決定的結論，都帶一個等級。五選一，沒有第六種，也沒有裸主張。**

這條規則存在的原因：模型最貴的失敗不是「不知道」，是**把推論寫得像事實**。讀者無法從措辭分辨「我跑過」與「我覺得應該」，於是把兩者當同一件事用。

## 五級

| 等級 | 意義 | 必須附上 |
|---|---|---|
| **已確認** | 直接讀到或實際跑過 | 檔案:行號、指令＋退出碼、或原始輸出 |
| **推論** | 由已確認的事實推導，但沒有直接觀察 | 推導依據（從哪幾個已確認推出來的） |
| **候選** | 有可能，但還沒排除其他可能 | 還沒排除的競爭解釋 |
| **未知** | 查了，沒查到 | 查過哪裡、還可以查哪裡 |
| **未驗證** | 有計畫或宣稱，但沒跑過 | 驗證方式與尚未執行的原因 |

**「未知」與「未驗證」不同**：未知是資訊缺口，未驗證是行動缺口。把「還沒跑測試」寫成「未知」會讓人以為沒辦法查。

## 用法

行內最短形式：

```
`src/auth.ts:42` 沒有做 token 過期檢查【已確認】
過期 token 會被接受，直到 revoke 清單同步【推論：依 42 行的分支與 revoke 的 5 分鐘週期】
可能還有第二條繞過路徑在 middleware【候選：middleware 有自己的驗證，還沒讀】
```

表格形式（報告、審查、架構盤點）另立一欄「證據等級」，不要靠語氣暗示。

## 不可降級也不可升級

- 沒有新證據，**不得**把候選寫成推論、把推論寫成已確認。
- 使用者催、時程緊、聽起來比較有信心——都不是升級的理由。
- 反過來，已確認的事實不因為對方不喜歡而降級。

## 什麼時候可以省略

只在**單一等級且已明說**的整段內容裡省略行內標記。例如審查報告開頭寫「以下 Findings 皆為已確認，除另行標註」，段內就不必逐條掛。

**不能省略的場合**：混用兩種以上等級的段落、給別人拿去決策的摘要、任何寫進文件或 commit／PR 的內容。

## 與其他規則的分工

- **要不要把結論翻譯到讀者的決策層** → [`register.md`](register.md) 的對話語域。白話可以省路徑與行號，**不能省等級**。
- **等級怎麼影響是否可以宣告完成** → [`core-rules.md`](core-rules.md) 第 4 條。有「未驗證」就不是完成。
- **Review Finding 的嚴重度分級** → 那是另一個軸（阻擋／重要／建議），與證據等級正交。一個「建議」也必須是「已確認」。
