# Runbook

用法在這裡。結構定義在 [WORKFLOW.md](WORKFLOW.md)，派發語彙在 [EXECUTION_MODEL.md](EXECUTION_MODEL.md)，不重述。

## 開工前只問一句

**「做完長什麼樣」，你現在講得出來嗎？**

| 答案 | 走 |
|---|---|
| 講得出來，而且很小 | [A：直接做](#a直接做) |
| 講得出來，是一個功能 | [B：規劃一輪](#b規劃一輪) |
| **講不出來** | [C：先撥霧](#c先撥霧) |
| 講得出來，但不確定**值不值得做** | [D：先蒐證](#d先蒐證) |

---

## A：直接做

```
開分支 → 爬最小實作階梯 → 做最小可動的東西 → 跑起來看 → 打掉或往下
```

**不能省的只有三件**：先開分支、回不了頭的決策寫 ADR（要過三條件閘）、收尾判斷有沒有 Lesson。

其他全部不用：規劃、切片、覆蓋率、文件。

**離開這條路的訊號**：你開始記不住做過哪些決定，或東西要交給別人。

---

## B：規劃一輪

`▸` = 一個 Process 邊界。

### ▸ 1 — 探索到切片（**不能中斷**）

載入 `se-design`，一口氣走完。

兩個最常被跳過、但決定後面順不順的：

| 步驟 | 規則 |
|---|---|
| **定接縫** | 沿用既有 > 新開；用**能觀測到行為的最高**接縫；越少越好（理想 1 個）。**先確認再寫第一個測試** |
| **切片** | 縱切穿過所有層。四判準：完整、可獨立驗證、**塞得進一個新 Process**、接縫已定 |

改共用型別這種爆炸半徑大的 → 不要硬塞成一片，走 expand → migrate 分批 → contract。

拆完 Process 用 `se-scheduling` 建 Ready Queue：**最大化初始 Ready Processes**，只有真依賴才建 `Depends on`，寫入衝突標成鎖不標成依賴。

### ▸ 2..N — 每個 Process 一段工作

```
新 context → 讀這片的計畫 → 爬最小實作階梯 → 在已確認接縫寫測試 → 跑 → commit
```

### ▸ 收尾

`se-two-axis-review` 兩軸 → `se-branch-lifecycle` 開 PR → `se-epiphany` 留 Lesson。

**兩軸不合併看**：Standards 與 Spec 分開報、不排名。「規範全過但做錯東西」是最貴的失敗，合併就看不見。

## C：先撥霧

`se-discovery`。**只產決策，不產交付物。**

```
▸ 1     命名終點 → 廣度掃描 → 建決策節點 → 連依賴 → 派 Thread Pool 蒐證 → 停
▸ 2..N  一個 Process 解一個 → 寫答案 → 更新地圖
▸ 清楚了 交棒 se-design
```

**兩個最容易搞錯的**：

1. 把霧預先切成 ticket 大小。判準是「現在能不能把問題**講精準**」，不是能不能回答。
2. 一個 Process 想解好幾個。狀態活在地圖裡，不活在 context 裡。

**想直接動手的衝動 = 已走到地圖邊界、該交棒**，不是可以加速。

> 這是最重的流程。握得住的功能走 B 就好。

---

## D：先蒐證

`se-feasibility`。**只產評估報告，不產規格也不改程式。**

適合：新技術、外部依賴、成本敏感、時程壓力、或你自己也不確定做不做得出來。

產出結論用機率區間（不給假精確的百分比），並明確允許「無法評估」。報告完問你：維持方案／縮小範圍／補驗證／停止。

## 卡住時查這裡

| 情況 | 動作 |
|---|---|
| 這個要求可能有兩種讀法 | 只問會改變產出的缺口（上限 3 個），其餘宣告假設往下做 |
| 一個想法要先被戳破再投入 | `se-clarify` 施壓模式：收斂成最缺的證據＋今天第一步＋可信度 |
| 答案在**人**身上 | `se-clarify` 問卷模式，別自己猜 |
| 講不出「做完長什麼樣」 | `se-discovery`，別開工 |
| 「該長什麼樣」爭不出來 | 做丟棄式原型；決策折回真碼，原型丟掉 |
| 一片塞不進一個 Process | 切太粗，回去重切 |
| 要在計畫外的位置寫測試 | 那是新接縫，先確認 |
| 規劃逼近 ~120k | 寫下結論、開新 Process |
| 工作樹有不認得的變更 | **停**，問人（race condition） |
| 兩個 Process 互相等對方 | deadlock：拆依賴或合併成一個 |
| 某個 Process 永遠排不到 | starvation：拆小它的寫入範圍 |
| 同一個 bug 修第三次 | 停止改 code，命名可能錯的那個假設，**寫 Lesson** |
| 想開 ADR | 三條件缺一就不寫 |

**ADR 三條件**：難以逆轉 ∧ 沒有背景會困惑 ∧ 真實取捨的結果。ADR 的價值來自稀有。

## 別做這些

| 反模式 | 改成 |
|---|---|
| 一個 Process 從規劃做到實作完 | 邊界斷開，切片各自新 Process |
| 為了看起來專業而派 Thread | 不需要隔離就 Coroutine |
| 跳過接縫確認直接寫測試 | 接縫是規劃階段的產出 |
| 橫切（先做完 schema 層再做 API 層） | 縱切，每片穿過所有層 |
| 依編號或「可能會衝突」建 `Depends on` | 那是鎖不是依賴 |
| 驗證時 grep 一下就說通過 | 跑真正的指令，讀真正的輸出 |
| 兩個 Worker 結果矛盾就取平均 | 顯式解決，或升級 Supervisor |
| 為顯而易見的選擇開 ADR | 三條件缺一不寫 |
| 預載整個 skill 庫求「完整」 | 只載當前步驟要的 |
| 小改動也跑完整規劃 | 走 A |
| 兩軸 review 合成一份排名 | 分開報，不排名 |
| 一次丟三個決策給人 | GIL：一次一個 |
| 做完就結束，什麼都沒留下 | `se-epiphany` |
