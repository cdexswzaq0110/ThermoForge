# Grill — 盤問

**最常見的失敗是誤解，不是無能。** 你以為對方知道你要什麼，等到東西做出來，才發現他從頭到尾理解成另一件事。

三個模式。開始前先判斷是哪一種：

| 情況 | 模式 |
|---|---|
| 需求還模糊，要一起想清楚 | **設計樹** |
| 想法已成形，要先被戳破再投入 | **施壓** |
| 答案在**別人**身上，不在你也不在文件裡 | **問卷** |

---

## 模式一：設計樹

把整個決策空間畫成一棵樹：每個決策分出掛在它下面的決策。

**分輪進行。**

**前緣（frontier）** = 所有「前置條件已經確定」的決策——也就是你**現在**就能問、不必先猜還沒聽到的答案的問題。

**一輪把整個前緣問完。** 每題編號，每題附上你的推薦答案。然後**等使用者回答**再進下一輪。

```
❓ **Q1** — **<問題標題>**：<問題本體，可以是多段，可以附選項>

➡️ <你的推薦答案＋一句理由與代價>
```

每一輪的回答會**重塑整棵樹**：確定的決策把前緣往外推，解鎖原本被它擋住的問題。重算前緣，問下一輪。

**一個答案取決於本輪還沒回答的問題 → 它屬於下一輪，不是這一輪。**

### 事實你查，決策他決

**找事實是你的工作，永遠不是使用者的。**

前緣問題需要環境裡的事實（檔案系統、工具、版本、既有實作）→ **派一個 Thread 去查**，不要問使用者你自己查得到的東西。

**不要為此卡住**：一個進行中的探索是一個未確定的前置條件，所以只有它下游的問題要等；**其餘的前緣現在就問**。

### 對話規則

- 一次一個決策，附推薦答案、理由與主要代價。
- 使用者提問或表示不理解 → **暫停原問題，先解釋**。解釋完可以在最後給建議選項，但不要用選項框——那會蓋掉你的解釋。
- 多個名詞可以一次解釋、一次給多個選項、允許複選。
- 使用者完全不熟悉時，從零說明並給推薦方案，**不要把技術調查丟回去給他**。

### 結束條件

**前緣空了**：設計樹的每個分支都拜訪過，沒有任何東西被默默假設掉。

**在使用者確認你們達成共識之前，不得開始動作。**

## 模式二：施壓

對象是一個**已經成形**的想法、計畫、選型或商業判斷。目標不是把它打死，是**在投入之前找出最缺的那塊證據**。

### 五軸

一輪跑完，每軸一到兩句，不寫長文：

| 軸 | 問什麼 |
|---|---|
| **前提** | 這件事成立需要哪些假設？哪一個假設垮了整件事就垮？ |
| **反例** | 什麼情況會讓它失敗？有沒有人試過同樣的事而失敗了？ |
| **成本** | 真實成本是什麼——不只錢，還有時間、維護、認知負擔、機會成本？ |
| **替代** | 有沒有更小的東西能買到八成的價值？「什麼都不做」的結果是什麼？ |
| **可逆** | 做錯了退得回來嗎？退回的成本多高？ |

### 強制收斂

五軸跑完**必須**收斂成三行，不能停在「以上供參考」：

```
最缺的證據：<一句話，具體到能去查>
今天第一步：<兩分鐘內做得到的動作>
可信度：<高／中／低>，因為 <一句話>
```

沒有這三行的施壓等於沒做。

### 缺口分級（要求有兩種讀法時用）

一個要求可能有多種解讀時，把缺口分三級：

| 級 | 定義 | 動作 |
|---|---|---|
| **A** | 猜錯要重做 | **問**（上限 3 個） |
| **B** | 猜錯要改，但不用重來 | 宣告假設，往下做 |
| **C** | 猜錯無所謂 | 直接決定，不提 |

**只問 A 級，上限三個。** 其餘明確宣告假設然後往下做——這是 GIL 的落地：一次只鎖住人最少的時間。

## 模式三：問卷

答案在**某個人**身上（領域專家、客戶、另一個團隊的同事），你猜出來的東西會被當成事實記下去——那比沒答案更貴。

### 先盤問「這次寄送」，不是主題

問你自己（或使用者）這幾題，決定問卷長什麼樣：

1. **要給誰填？** 他的語域是 L1 還是 L3？（`rules/register.md`）
2. **你需要拿回什麼？** 具體到「拿到之後我就能做 X」。
3. **他會怎麼填？** 非同步自己填，還是你們一起開會走一遍？
4. **他不填會怎樣？** 這決定要不要給預設值與截止點。

### 產出

一份 Markdown 問卷，寄出去就能填：

```markdown
# <主題> — 請你幫我確認幾件事

> 背景：<兩三句，用對方的語域>
> 我需要這些答案來：<做什麼>
> 大約需要：<N> 分鐘

## 1. <問題標題>

<問題本體，用對方聽得懂的話>

- [ ] 選項 A — <一句後果>
- [ ] 選項 B — <一句後果>
- [ ] 其他：＿＿＿＿

_如果不確定_：<你的預設假設是什麼，以及照這個做的後果>

---

## 我這邊的假設（如果沒回覆，我會照這個做）

| 項目 | 假設 | 錯了的代價 |
|---|---|---|
```

### 邊界

- **問卷是收集答案，不是取得核准。** 對方回答了不等於他核准了範圍。核准要另外明確走一次。
- 每題附「不確定的話我會怎麼做」——這讓沒回覆也不會卡住。
- 回填後，答案落到規格或計畫裡，並標明**來源是誰、什麼時候答的**（`core-rules` 第 2 條）。

---

## 三個模式共通的禁止事項

- 不得為了顯得認真而多問。**每個問題都要能改變產出**，不能就刪掉。
- 不得把你查得到的事實包裝成問題丟回去。
- 不得在使用者確認共識之前開始實作。
- 不得一次丟出三個以上需要人拍板的決策（GIL）。
