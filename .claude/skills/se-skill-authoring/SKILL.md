# Skill Authoring — 寫給 Agent 看的文件

包裝形式不同，寫法一樣：讓 Agent **每次跑同一套流程**（不是產出同一份輸出）。

---

## 一、Context 指標

**Context 指標**是常駐在 context 裡、指向 context 外材料、並且編碼了「什麼時候去拿」的一段文字。skill 的 `description` 是指標；`CLAUDE.md` 裡指向某份文件的一行也是同一種東西。

**決定 Agent 何時去拿材料的是指標的措辭，不是它指向什麼。** 一份非拿不到不可的材料配一個措辭模糊的指標，是**變異性 bug**——先把措辭磨利，磨不動才考慮把材料內聯。

指標做兩件事：說清楚材料是什麼、列出**應該觸發去拿它的分支**。常駐指標的每個字每輪都在花錢，所以修剪要比正文更狠：

- **把最能觸發的詞放最前面**——指標是它做觸發工作的地方。
- **一個分支一個觸發詞。** 同義詞換句話說一次，是同一個分支寫了兩遍，合併掉。
- **砍掉正文已經帶著的身分敘述。**

## 二、兩種負擔

每份文件與每個指標都在花兩種預算之一：

- **Context 負擔**——常駐材料佔的視窗：一行 `CLAUDE.md`、一段 skill description，不管有沒有觸發都在花 token 與注意力。
- **認知負擔**——花在**人**身上的：有哪些文件、什麼時候該找哪一份。人是那個索引。這**不是要最小化的成本**——它是人的能動性的價格。人的判斷重要的地方要花，不重要的地方拿掉。

只透過指標才拿得到的材料，用一行指標的代價換掉了 context 負擔；完全沒有指標的材料，整份騎在認知負擔上。

## 三、資訊層級

文件由兩種內容組成：**步驟**（Agent 依序執行的動作）與**參考**（按需查閱的定義、規則、事實）。兩者可以自由混合。

核心決定是每一塊坐在**資訊層級**的哪一階——依「Agent 多急著要它」排序：

1. **檔內步驟**——主階：Agent 做什麼，照順序。
2. **檔內參考**——按需查閱。常常是合法的扁平同儕集合（一次審查的全部規則放同一階），這是好安排，不是壞味道。
3. **揭露式參考**——推到另一個檔案，由指標觸發才載入。

推太少頂端會腫，推太多會藏起 Agent 其實需要的材料。**這個張力就是全部的決定。**

**漸進揭露**是在階梯上往下移。不主要是 token 最佳化——它是**保護層級**的方法。最乾淨的判準是**分支**：每個分支都需要的內聯，只有部分分支會走到的推到指標後面。

**同位**是檔內的搭檔：階梯決定往下多遠，同位決定到了那階旁邊放什麼。把一個概念的定義、規則、注意事項放在同一個標題下，不要散落。判準：這份文件應該讀起來像**寫給 Agent 的文件**。

**蔓延**是這裡的失敗模式：文件單純太長，即使每一行都活著也獨一無二。注意力在多餘的長度上變薄。解法就是階梯。

## 四、步驟與完成判準

每個步驟結束在一個**完成判準**上。兩個性質讓它成為槓桿：

- **清晰度**——Agent 分不分得出做完與沒做完？模糊的界線（「達成理解」）會招來**提前完成**：注意力滑向「快結束了」。防守順序：**先把界線磨利**（局部、便宜）；只有在它本質上就模糊**而且**你確實觀察到趕工時，才把後面的步驟藏起來——而藏起來只有跨越真實 context 邊界才有效（交接或派出 Thread／Process；同 context 內的呼叫不會清掉任何東西）。
- **要求量**——它要求多少。「每一個被修改的 model 都要交代」逼出的工作量遠大於「產出一份變更清單」。要求量驅動**腿力**（Agent 在工作中自己去挖的深度），而且不綁在步驟上：「每一條規則都套用過」約束一堆扁平參考的力道，等同於「每一步都做完」約束一段序列。

最強的判準同時**可檢查**且**窮盡**。

## 五、引導詞

**引導詞**是模型預訓練裡已經存在、Agent 跑這份文件時會拿來思考的緊湊概念（_lesson_、_seam_、_tracer bullet_、_ready queue_、_mutex_）。當成 token 重複、絕不當成句子重複，它會累積出一個分散式的定義，用最少的 token 錨定一整片行為。

自創詞在你定義清楚時可行，但**自創的詞徵召不到任何先驗**——你用定義的 token 去買一個既有詞免費送你的東西。**先找既有的詞。**

> 這正是本配置 把任務切分整套借用 process／thread／mutex／ready queue 的理由：你已經知道兩個 thread 同時寫同一塊記憶體會出事，那份直覺不用重新教。

它錨定兩次。在正文是**執行**：每次那個詞出現，Agent 伸手拿同一套行為。在指標是**調用**：當同一個詞活在你的提示、你的文件、你的 codebase 裡，Agent 更可靠地把那份共享語言連到材料上。

**去獵重構機會**：一個在三個地方各自展開的三連詞、一個花一整句去比劃一個概念的指標——每一段都在求著塌縮成一個 token。

**否定**是這條槓桿旁邊的失敗模式：用禁令去導向會把被禁的行為**拉進** context，讓它更可得而不是更不可得。_不要想大象_，然後滿腦子都是大象。**下正面指令**——講出目標行為，讓被禁的那個從沒被說出口。禁令只有在你無法用正面說法表達的硬護欄時才值得留，即使那時也要配一個正面目標。

## 六、修剪

- **每個意思只留一個真相源。** 重複要付維護與 token 成本，還會讓一個意思在階梯上的顯著度膨脹到超過它的真實排名。（跟引導詞正好相反：那是刻意重複 token，從不重複意思。）
- **環境本身也是真相源**——`package.json` scripts、設定檔、目錄結構、`--help` 輸出。重述環境的文件是一份**快取**：只有查找很貴時才值得。**快取那些 Agent 看不到的東西**：沒寫下來的慣例、選擇背後的理由、沒有設定檔會招認的坑。一個檔案、一個指令查得到的，留給環境，那裡不會過期。
- **檢查每一行的相關性**：它還跟這份文件做的事有關嗎？
- **一句一句獵 no-op**：模型預設就會照做的指令，付了負擔卻什麼都沒說。判準——**它有沒有改變預設行為？** 這是相對於模型、不是相對於讀者。兩個人爭論某句是不是 no-op，是在爭論預設值是什麼，用**跑一次文件**解決，不用辯論。一句失敗就**刪掉整句**，不要修字。

## 七、調用軸（出貨前必須確定）

每個 skill 只能是兩者之一：

| | 使用者調用 | 模型可調用 |
|---|---|---|
| 誰能觸發 | **只有人打出它的名字** | 模型或人 |
| frontmatter | `disable-model-invocation: true` | 省略 |
| `description` 寫給誰看 | **人**——瀏覽 slash command 時看的一行摘要，拿掉觸發語 | **模型**——保留豐富觸發措辭，讓自動調用會發火 |
| 典型職責 | 編排 | 可重用的紀律 |

判準：**模型能不能自主地有用地伸手拿這個？** 能就是模型可調用。

**使用者調用的 skill 可以呼叫模型可調用的 skill，但不得呼叫另一個使用者調用的 skill。**

依賴用 `/skill` 式的散文呼叫（「載入 `se-minimal-change`」），**不要**深層的 `../other-skill/FILE.md` 交叉引用。共用的參考文件住在擁有它的那個 skill 裡面，別的 skill 用調用它來取得材料。

## 八、出貨門檻

一個 skill 要出貨，過這五關（其中任一沒過就是還沒好）：

| 關卡 | 要求 |
|---|---|
| **確定性優先** | 必須不能出錯的步驟，用程式或明確清單保證，不靠模型的注意力。動態決策與動態取材才交給模型 |
| **參考有來源** | 深度內容按需載入，且標明出處與授權 |
| **證據勝過感覺** | skill 做的每個主張都要可檢查 |
| **預設本機、預設不外送** | 沒宣告就不做網路呼叫；不要求 `curl \| bash` |
| **出貨前測過** | 用真實輸入測過，不只 happy path fixture |

## 九、觸發測試（改 description 必跑）

改動 `description` 之後，至少跑一次雙向觸發測試：

```
should-trigger:    3 個應該載入它的真實請求
should-not-trigger: 3 個「聽起來像但不該載入」的請求
                    （通常是相鄰 skill 的地盤）
```

**兩邊都要過。** 只測 should-trigger 會養出一個什麼都搶著載入的 skill——那比不載入更貴，因為它排擠掉真正該載入的那個。

相鄰 skill 之間的區辨要寫進 `skills/INDEX.md` 的「別選錯」欄。

## 十、品質評分（要比較兩個版本時）

盲評：把回應標成 `A`／`B`／`C`，不暴露條件名稱。每個維度 1（失敗）到 5（優秀）。

| 維度 | 權重 | 量什麼 |
|---|---:|---|
| 正確性 | 35% | 事實與技術準確；必要細節保留 |
| 自主性 | 25% | Agent 做了 Agent 該做的工作，沒把可避免的工作推回給人 |
| 可行動性 | 20% | 下一個動作好找、好執行 |
| 安全性 | 10% | 風險、確認、歧義處理正確 |
| 精簡度 | 10% | 沒有填充與岔路；簡短不至於刪掉必要內容 |

出現以下任一標 `blocker`：危險指令、實質事實錯誤、沒有遵守明確的輸出契約、Agent 自主性退化到無法完成任務。

**只有同時滿足才發布**：沒有 blocker；正確性與安全性各自不低於基線 0.1 分；加權總分高於基線。

## 完成條件

- 調用軸已確定，frontmatter 與 `description` 的讀者相符。
- SKILL.md 超過約 200 行的部分已下放到 `references/`。
- 雙向觸發測試已跑，`skills/INDEX.md` 的「別選錯」欄已更新（維護契約第 1 條）。
- 沒有把環境已是真相源的東西抄一份進來。
- 沒有純否定式的指令沒配正面目標。
