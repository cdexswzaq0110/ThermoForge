# Epiphany — 領悟帳本

**這套配置的長期記憶。** Process 會死，context 會 compact，對話會結束——帳本不會。

一則 Lesson 要同時滿足兩條才值得寫：

1. **撞出來才知道的**——查文件就有的不算，那是環境的真相源，寫下來只會過期。
2. **下一輪還會用到的**——只在這次任務成立的細節不算，那是暫態。

兩條都過才寫。**不寫也要是判斷過的結果，不是忘記。**

---

## 模式一：捕捉（收工時）

觸發：一輪工作結束、`core-rules` 第 6 條、或使用者說「記下來」。

### 三個問題

1. 這一輪有什麼是**開始前不知道、現在知道了**的？
2. 那件事**下次還會遇到**嗎？
3. 如果下次是另一個人（或全新 context 的你）碰到，這一頁**夠不夠讓他直接跳過這個坑**？

三個都是 yes 才寫。任一個 no，說一句「本輪無 Lesson，原因：⋯」然後結束。

### 寫在哪

`docs/lessons/<NNNN>-<slug>.md`，四位流水號。同時在 `docs/lessons/INDEX.md` 加一行指標。

**INDEX.md 只放一行指標，不放內容**——它每次召回都會被讀，長度就是成本。

### 格式

```markdown
---
id: L0007
date: 2026-08-14
outcome: useful          # useful | dead_end | corrected
tags: [windows, powershell, git]
anchors:                 # 這則教訓貼在哪些檔案上；用來偵測失效
  - scripts/build.ps1
  - .github/workflows/ci.yml
supersedes:              # 這則取代了哪一則（可空）
hits: 0                  # 被召回並確實有用的次數（候選門檻，不是升級門檻）
generalizes_to:          # MUTATE：它泛化到哪一「類」？填不出來就升不了級
validated:               # VALIDATE：leave-one-out 的結果。未驗過留空
---

# <一句話：下次遇到什麼情況、該做什麼>

## 觸發情境
遇到什麼才會用到這則。寫得夠具體，讓召回時能命中。

## 領悟
撞出來才知道的那件事。【證據等級＋證據】

## 為什麼會撞到
原本的假設是什麼、錯在哪。**這一段最值錢**——同一個錯誤假設會生出一整族的坑。

## 下次怎麼做
具體動作。能寫成指令就寫指令。

## 失效條件
什麼變了這則就不再成立（版本、平台、依賴、專案結構）。**填不出來的，標記 `no-trigger`。**
```

### outcome 三選一

| 值 | 意義 |
|---|---|
| `useful` | 這個做法有效，下次照做 |
| `dead_end` | 這條路走不通。**同樣值得記**——省下的是下次重走一遍的時間 |
| `corrected` | 我原本以為 X，實際是 Y。錯誤假設本身就是內容 |

`dead_end` 常被跳過，這是錯的。**「我試過 A，因為 B 所以不行」和「用 C」一樣有價值。**

### 反模式

| 不要寫 | 因為 |
|---|---|
| 「要注意型別安全」 | 沒有觸發情境，永遠召不回來 |
| 「修好了 auth 的 bug」 | 那是 commit message，不是教訓 |
| repo 自己就記錄的（結構、歷史、CLAUDE.md 已寫的） | 環境是真相源，抄一份只會漂 |
| 沒有失效條件的技術細節 | 會爛掉且沒人知道它爛了 → 至少標 `no-trigger` |

## 模式二：召回（開工時）

觸發：要開始一件工作，而它**似曾相識**。

1. 讀 `docs/lessons/INDEX.md`（只有指標，很便宜）。
2. 用當前任務的關鍵字比對 `tags` 與觸發情境，挑**最多 3 則**展開讀。
3. 命中且確實有用 → `hits` +1。

### 失效檢查

展開一則之前，看它的 `anchors`：

```bash
git log --oneline -1 -- <anchor>          # anchor 最後改動時間
```

若 anchor 的最後改動晚於 Lesson 的 `date` → 在引用時標記 **「程式已變動，需重新驗證」**，不得直接當成已確認事實。

這條直接繼承 `evidence-grades`：**一則過期的 Lesson 是「候選」，不是「已確認」。**

### 不要一次載入全部

召回不是「把帳本讀一遍」。最多 3 則。帳本長大不該讓每次開工變貴——這就是 INDEX 與內文分離的理由。

---

## 模式三：回顧（定期／滿 20 則）

觸發：使用者說「回顧」、帳本超過 20 則、或每個模型大版本。

四件事，依序：

### 1. 去重

同一個觸發情境的多則 → 合併成一則，新的 `supersedes` 舊的，舊的移到 `docs/lessons/archive/`。

### 2. 標失效

批次跑 anchor 檢查。anchor 檔案已刪除或大改的 → 標 `stale`，並判斷：重新驗證、改寫、或封存。

### 3. 升級（**這個模式最重要的一步**）

**`hits >= 3` 是候選門檻，不是升級門檻。** 次數只證明「這件事又發生了」，不證明「那條規則有用」——**召回計數不是因果驗證**。只靠次數升級，帳本就只是把記憶檢索換了個名字。

升級要過四關，依序，缺一不可：

| 關 | 問什麼 | 過不了的話 |
|---|---|---|
| **1 SCAN** | 這則 Lesson 指得出**具體的失敗**嗎？（檔案、指令、可重現的觀察） | 不是教訓，是感想。留在帳本 |
| **2 VALIDATE** | **拿掉這條、其餘完全不動，那個失敗會重現嗎？** | 沒驗過的一律標「待驗」，不得升級 |
| **3 MUTATE** | 它泛化到哪一**類**？只在這一個實例成立的，寫進 lesson 就好 | 升級的是類別，不是實例 |
| **4 SOLIDIFY** | 有沒有一個**跑得起來的檢查**能守住它？ | 帶不出檢查的，只能留在 lesson 或降級成 skill |

**第 2 關是整套配置的核心，也是最常被跳過的一關。**

做法：leave-one-out。只拿掉那一條，其餘配置**完全相同**，replay 那個已知失敗（不是新造的漂亮任務）。判準是「**能不能重現那個已知失敗**」——這比泛化 effect size 便宜得多，而且正好就是 `ABLATION.md` 要的「失敗證據」。

⚠ **不要用 bundle 對照**（有規則 vs 沒規則 vs 完整配置）。一次變動太多變數，卻要把結果寫進單一條規則的證據欄，那是錯誤歸因。

⚠ **「沒測到差異」不等於「無效」。** 它只說明：在這批任務、這個模型版本、這個樣本數下沒測到。要宣稱等效，必須先定義可接受差距。

第 3 關的產物寫進 frontmatter 的 `generalizes_to`。例：一則「PowerShell 讀寫 UTF-8 原始碼會毀檔」的教訓，類別是**「工具鏈的編碼往返」**，不是 PowerShell。升級成規則的是類別。

第 4 關的檢查形式，依序找第一個成立的：hook（判定寫得成 shell）→ 測試 → skill 裡的清單。**三種都給不出來，就代表它還不夠具體到能常駐。**

四關都過之後，判斷該升級成什麼：

| 這則教訓的形狀 | 升級成 | 必須通過 |
|---|---|---|
| 每次工作都成立，而且與模型預設行為不同 | `rules/` 常駐規則 | **四關全過**，且 [ABLATION.md](../../ABLATION.md) 的失敗證據欄填的是 VALIDATE 的結果，不是 Lesson 本身 |
| 一套可重用的方法或清單 | `skills/` 新 skill 或既有 skill 的一段 | `se-skill-authoring` 的觸發測試 |
| 一次不可逆的技術取捨 | ADR | 三條件閘 |
| 專案詞彙 | `CONTEXT.md` | — |
| 環境事實（指令、路徑、版本） | 專案的 `CLAUDE.md` | 環境是否已是真相源 |

**升級後原 Lesson 不刪除**，改標 `outcome: promoted` 並註明升級到哪裡。它是那條規則的失敗證據來源，刪掉就等於刪掉 ABLATION 的證據。

> 這條路徑是這整套 配置 的閉環：
> **機遇（撞到）→ 領悟（寫成 Lesson）→ 智慧（升級成常駐規則）。**
> 沒有升級路徑的帳本只是日記；沒有帳本的常駐規則沒有證據。

### 4. 降級

反過來：一條常駐規則若在消融時發現沒有支撐它的 Lesson 或失敗證據 → 降回 skill，或刪除。

---

## 邊界

- 只讀寫 `docs/lessons/` 與升級目標檔。不改程式。
- 升級成常駐規則**必須**同步在 ABLATION 分類表新增一列，否則違反維護契約第 6 條。
- 一輪最多寫 **1 則** Lesson。寫兩則通常代表其中一則不夠格，或這一輪其實是兩輪。
- 不把 Lesson 當成 TODO。待辦進 issue tracker，帳本只放**已經學到**的。

## 完成條件

**捕捉**：檔案已寫入、INDEX 已加行、outcome 與失效條件都已填（或明確標 `no-trigger`）。
**召回**：最多 3 則已比對，過期的已標記為需重新驗證。
**回顧**：去重、標失效、升級判斷都已跑過，升級項已在 ABLATION 登記。
